# Tasks

## 1. Hardware-free logic in the core

- [ ] 1.1 Add `core/wifi_drive/drive_mode.{h,cpp}` (D1): the boot decision from the setup request and the switch level (setup wins; open is Bluetooth drive, closed is WiFi drive), and the switch notice (shown once the level has differed from the boot mode for 100 ms, cleared once it has matched for 100 ms); list it in the root `platformio.ini`. Verify with a new `test/test_drive_mode` via `mise run test`: all four boot combinations, a 99 ms and a 100 ms change, bounce shorter than 100 ms, and the notice clearing after the switch returns.
- [ ] 1.2 Add `core/wifi_drive/handheld_controller.{h,cpp}` (D3, D4): datagram validation (length, version, type, CRC), the sender lock, the sequence rule, the 150 ms liveness, session baselines, translation of the three counters with the mode and gesture they carry, Sleep until the first mode request of a session, pass-through of the analogue fields, the controller-connected flag, the e-stop flag kept through a lapse, and outcome counts; list it in `platformio.ini`. Verify with a new `test/test_handheld_controller` via `mise run test` covering every scenario of the `wifi-drive` spec's datagram, single-handheld, liveness, counter-translation and e-stop requirements, including a restarted app whose counters start at zero (no bridge counter change), sequence wrap from 255 to 0, a 149 ms and a 151 ms gap, and a 22-byte datagram holding a valid frame plus one byte (discarded).
- [ ] 1.3 Give `protocol::Decoder` the raw bytes of the frame `next()` has just returned, and give `access_point` the WiFi drive network name (`spooder-drive-` + 4 MAC digits) beside the setup one (D2, D3). Verify via `mise run test` with new cases in `test/test_protocol` (the raw bytes of each frame type in `test/golden/protocol_v3.txt` equal the golden bytes, including after a garbage prefix) and `test/test_setup_entry`, where the access-point tests live (both names from one MAC, the size limit), and that `test/test_protocol_golden` still passes unchanged.
- [ ] 1.4 Extend `core/status/status_screen` for WiFi drive (D6): the drive page's controller field, the link page's network, password and handheld lines, and `SWITCH MOVED: RESTART` in the status strip in the warning tone. Verify with new cases in `test/test_status_screen` via `mise run test` (each status-display scenario of this change, every new line within its field width, Bluetooth drive pages unchanged), and `mise run lint`.
