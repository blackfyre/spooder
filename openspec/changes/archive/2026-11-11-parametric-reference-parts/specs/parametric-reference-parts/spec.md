# Spec Delta

## Purpose

Parametric solids of the reference printed parts (Aecert's hexapod and LilyGO's case shell), built from named dimensions, checked against their STL meshes and exported as STEP that opens in FreeCAD and solidcraft.

## ADDED Requirements

### Requirement: Parts built from named dimensions
Each converted part SHALL be generated by code from named, documented dimensions measured from its reference STL, and built from modelling features (sketches, extrusions, holes, chamfers, fillets), so that changing a dimension and rebuilding yields the changed part. A part SHALL NOT be produced by converting the mesh's triangles into a solid: part code SHALL NOT read files, and the build SHALL fail on a file in a parts folder that imports anything outside the stated allowlist or calls a file-reading or code-loading function. Each part SHALL be built in its reference STL's own coordinate frame. The reference files SHALL stay unchanged.

#### Scenario: A dimension changes
- **WHEN** a named dimension of a part is changed and the build is run in check mode
- **THEN** the part is rebuilt with that dimension, and the gates report its deviation from the STL

#### Scenario: A part file reads a mesh
- **WHEN** a file in a parts folder imports a module outside the allowlist, imports a mesh- or file-import function, or calls `open`
- **THEN** the build fails naming the part file, and writes no files

#### Scenario: Coordinate frame kept
- **WHEN** a built part is compared with its STL
- **THEN** both are compared in the STL's coordinates, without any alignment or transform

### Requirement: Parts discovered without a registry
The build SHALL find every part from its own file in a source's parts folder, with no shared list of parts. Each discovered part file SHALL declare exactly one part, except a mirrored pair; helper files, which the build does not discover, declare none. A mirrored pair SHALL be modelled once in one file that declares both sides, the second only by naming the first and the mirror plane, so that the build makes it as the mirror of the first; each side SHALL be checked against its own STL. The build SHALL fail on a discovered file declaring no part, more than one part (other than a mirrored pair), or a second side with its own model. Adding a part SHALL need only its part file, its committed STEP output, its source README's section and a changelog entry.

#### Scenario: A part file is added
- **WHEN** a new part file is placed in a source's parts folder
- **THEN** the next build checks and exports that part without any other file being edited

#### Scenario: A mirrored pair
- **WHEN** a part file declares a left and a right side, one the mirror of the other
- **THEN** the build checks each side against its own STL and exports each side

### Requirement: Gates against the reference STL
In check mode the build SHALL check each part and report every failure by part and gate. A part SHALL pass only when:
- it is one valid, closed solid;
- its volume lies within the stated volume tolerance of its STL's;
- the symmetric surface deviation, from points on the part's surface to the STL and from points on the STL to the part, has a maximum and a 95th percentile within the stated limits, where the points on each side include every vertex of that side's mesh subdivided to a stated maximum edge length as well as points sampled by area, and the documentation states the resulting bound on the unsampled deviation;
- each face of its bounding box lies within the stated tolerance of the STL's.

The tolerances SHALL be stated in the documentation with their justification against the STL's tessellation chord error. A part that cannot meet a gate with feature-based modelling SHALL have a documented, per-part exception naming the feature and the amount; the global tolerances SHALL NOT be loosened for it.

#### Scenario: A part fails a gate
- **WHEN** any part fails any gate
- **THEN** the build names the part, the gate and the measured value against its limit, exits non-zero, and writes no files

#### Scenario: Deviation measured both ways
- **WHEN** a part lacks a feature the STL has, or has a feature the STL lacks, standing more than the maximum deviation plus the stated sampling bound off the other surface, however small its area
- **THEN** the surface deviation gate fails

#### Scenario: Documented exception
- **WHEN** a part declares an exception for one gate
- **THEN** that part is checked against the exception's limit, the build prints the exception, and every other part keeps the global limits

### Requirement: STEP export written only after re-reading
When every part passes, the build SHALL write each part as STEP into a staging folder, re-read each file there as one solid with the built part's volume and bounding box, and only then replace the committed STEP folder as a whole, so that the folder never holds a mixture of old and new files; a run interrupted during the replacement SHALL leave the old files complete, and the next build SHALL restore them before anything else. STEP files of parts that no longer exist SHALL be removed. An unchanged part SHALL write an unchanged file.

#### Scenario: Export succeeds
- **WHEN** all gates pass and every staged STEP re-reads correctly
- **THEN** the STEP folder holds exactly one file per current part

#### Scenario: Re-read fails
- **WHEN** a staged STEP does not re-read as one solid with matching volume
- **THEN** the build reports it and the committed STEP folder is left as it was

#### Scenario: Replacement fails
- **WHEN** replacing the committed STEP folder with the staged one fails part way
- **THEN** the committed STEP folder holds either all the old files or all the new ones, or is restored with all the old files by the next build

### Requirement: Import checks in FreeCAD and solidcraft
The build SHALL check that each committed STEP imports as one closed solid, with volume within the stated tolerance of the built part's, in FreeCAD run headless and in solidcraft-cli. Each import check SHALL report its result per part, with the tool's version. When a tool is not installed, its check SHALL report `SKIPPED` with the reason, and the build's summary SHALL say which checks were skipped; it SHALL NOT report a pass. A failed import check SHALL fail the build. The tool versions last checked SHALL be recorded in the documentation.

#### Scenario: Tool present
- **WHEN** FreeCAD or solidcraft-cli is installed and a STEP imports as one solid with matching volume
- **THEN** the check reports a pass for that part with the tool's version

#### Scenario: Tool absent
- **WHEN** FreeCAD or solidcraft-cli is not installed, as on CI
- **THEN** the check reports `SKIPPED` naming the missing tool, and the summary lists it as skipped, not passed

#### Scenario: Import mismatch
- **WHEN** a STEP imports as more than one solid, or as an open shell, or with a volume outside tolerance
- **THEN** the build fails naming the part, the tool and the measured value

### Requirement: Documentation of the parametric parts
The parametric parts folder SHALL carry a README stating how a part is added, the part file's contract, the gates and their tolerances, the import checks with the tool versions checked, and how to run the build. Each source SHALL carry a README stating its source repository, the reference commit, its licence (for Aecert's parts: that upstream states no licence, said plainly), and a parts table per group, each part with its STL, its STEP file and any gate exception.

#### Scenario: A part is listed
- **WHEN** a part's file exists in a source's parts folder
- **THEN** that source's README lists the part with its STL and STEP file

#### Scenario: An exception is documented
- **WHEN** a part declares a gate exception
- **THEN** the source README names the feature responsible and the amount by which it exceeds the global limit

### Requirement: The frame group
The Aecert source SHALL include the frame group: Frame Top, Frame Bottom, Servo Mount, Bearing Axle Mount and Hubcap, each passing the gates and exported as STEP.

#### Scenario: Frame group built
- **WHEN** the build is run
- **THEN** it checks and exports the five frame parts, each against its STL in `hardware/aecert-hexapod-v1/stl/`

#### Scenario: A frame part is missing
- **WHEN** any of the five frame parts is not declared in the Aecert source's parts folder
- **THEN** the unit tests fail naming the missing part
